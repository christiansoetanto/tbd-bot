- 2026-08-03: Outage. The bot was dead in Discord for ~33 hours — `tbd_bot_handler_duration_seconds_count{handler="cm_question_limiter"}` froze at 449 on 08-01 19:00 UTC — while the container reported `healthy` the whole time. The `BOTTOKEN` had been reset, so REST calls returned 401 and the gateway could not re-identify. Two things hid it. The healthcheck probes `/metrics`, which the HTTP server serves independently of the gateway, so a dead bot is indistinguishable from a live one; the open question below about `tbd_bot_github_api_failures_total` is no longer hypothetical, and the same gap applies to Discord. And the container's env was frozen at its 07-29 05:56 creation: both `.env` files were edited hours later, but 31 `docker restart` calls never re-read `env_file`, so the container ran a stale `GITHUBAPITOKEN` and failed GitHub with `Bad credentials` from 07-30 — Office of Readings pushed nothing for four days. Only `docker compose up -d --force-recreate` picks up `.env`. Recovered by regenerating the token into both `.env` files and recreating. One loose end left unchased: the container logged 32 starts between 07-29 and 08-01 (`RestartCount=31`) with `OOMKilled=false`, cause unknown. It is 0 since the recreate, so it was not pursued.

- 2026-08-03: PR #21's `Go` workflow failed at Build: `go.mod:3: invalid go version '1.25.0': must match format 1.23`. `.github/workflows/go.yml` pinned `go-version: '1.20'`, whose module parser predates three-part `go` directives. Same class as the `golang:1.22-alpine` builder bug found on 07-29, but CI installs its own toolchain and so drifts independently of the Dockerfile — `TestDockerfileGoVersionSatisfiesGoMod` could never have caught it. Now asserted by `TestCIWorkflowGoVersionSatisfiesGoMod`. Also bumped `checkout@v3`/`setup-go@v4` to v4/v5 to clear the Node 20 deprecation warning.
